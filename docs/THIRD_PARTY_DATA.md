# Third-party data

## US ZIP codes (`public.us_zip_codes`, migration `0004f_us_zip_codes`)

Generated by `scripts/zip-data/build-migration.py` from two public data files. The files were read as data only:

| Data | Source | License |
|---|---|---|
| ZIP → city, state | npm `zipcodes@8.0.0` (`lib/codes.js`). Data from federalgovernmentzipcodes.us | BSD, © 2007 Dav Glass |
| ZIP → time zone | npm `zipcode-to-timezone@0.0.9` (`zipcodes.json`). Data from the zip2timezone project | MIT, © 2016 Dor Technologies |

Changes made by the script:
- **US states + DC only.** Territories and military ZIPs are left out.
- **Time zones** are reduced to the ones a stop can use (`STOP_TIME_ZONES` in `src/lib/us.ts`).
- **Corrections by 3-digit ZIP prefix**, where the source has whole areas in the wrong zone:
  - western Kentucky (420–424) → Central
  - northwest Indiana (463–464) → Central
  - southwest Indiana (476–477) → Central
- **ZIPs with no time zone** in the source use the state's default zone.

The data is from around 2012–2016, so newer ZIP codes are missing. Then the user types city and state by hand.
In states with two time zones the form asks to check the zone.
To refresh the data, rerun the script on newer files in a new migration. Never edit `0004f`.
